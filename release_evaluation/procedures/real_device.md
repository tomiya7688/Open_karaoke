# 実機評価手順（Windows WASAPI）

**これは手順書であり、実施結果ではない。** 実施前の項目は`report.json`で`unverified`のままにする。
結果は下の記録様式で別ファイルに残し、`evidence_ref`で参照する。個人情報・非公開音源は記録しない。

## 前提（記録必須）
- アプリ版: `app_sha`（40桁）、配布物のSHA-256
- 機材: OS版、オーディオインターフェース/USB機材の型番、ドライバ版、共有/排他モード、サンプルレート（48kHz）、バッファサイズ
- ループバック経路: 出力→入力を物理ケーブルまたはループバックデバイスで接続（方式を記録）
- 担当Issue: 遅延・クロック契約は#40、リソース分離は#43

## A. ループバック遅延（metric: `audio_clock/loopback_latency_p95_ms`）
1. アプリの遅延校正（#40の手順）を実行し、校正値を記録する。
2. ステップ/クリック信号を再生し、ループバック入力で検出するroundtripを**200回以上**計測する。
3. 中央値とp95（ms）を記録する。外れ値を除外しない。除外した場合は理由と件数を記録する。
4. 再生・マイクのデバイス切替（既定デバイス変更）後に再計測する。

## B. クロックドリフト（metric: `audio_clock/clock_drift_ppm`）
1. 同一のループバック構成で、一定間隔のクリックを**30分以上**再生・録音する。
2. 検出時刻と期待時刻の差を線形回帰し、傾きをppmで記録する。

## C. デバイス抜き差し（metric: `device/hotplug_recovery`、成功率0〜1）
1. 歌唱中に、マイクUSBを抜く→**10秒待つ**→挿す、を**10回**行う。出力デバイスでも同様に行う。
2. 各回で「エラー表示」「クラッシュ無し」「手操作無しまたは定められた操作のみで再開」を判定する。
3. 成功した回数/試行回数を記録する。失敗時はログの該当箇所（個人情報を除く）を残す。

## D. 長時間稼働（metric: `endurance/long_run_underruns`）
1. 店舗相当の連続時間（**未決**。決まるまで暫定8時間として記録し、報告に暫定と明記）で、再生・解析・採点を繰り返す。
2. underrun回数、最大メモリ、CPU使用率の推移、クラッシュの有無を記録する。
3. 解析ジョブ同時実行時の再生の途切れ（#43）を確認する。

## 記録様式
```text
実施日 / 実施者 / app_sha / 配布物SHA-256
機材: OS, デバイス型番, ドライバ版, モード, サンプルレート, バッファ
項目: A|B|C|D
結果: 値, 試行数, 失敗数, 除外した外れ値と理由
証拠: ログ/CSVの保存場所とSHA-256
逸脱: 手順からの変更点
判定: 閾値(校正済みなら版付き) と status(pass|fail|unverified)
```
閾値が未校正（`null`）の間は、実測値を記録しても`status`は`unverified`とする。
