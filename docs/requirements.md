# 要件

## 目的

Open_karaoke は、ユーザーが原曲を用意するだけでカラオケに必要なデータを可能な限り自動生成し、そのまま歌唱・音程表示・採点まで行えることを目標とする。

人間による修正は可能にするが、通常利用では修正を前提としない。低信頼箇所もまず自動再解析し、機械側で可能な限り正解へ収束させる。

## 入力

### 原曲

以下を読み込めることを目標とする。

- WAV
- AAC
- MP3
- MP4

動画ファイルの場合は音声を抽出して解析する。

### 参考データ

以下は任意入力とする。

- 既存歌詞
- MIDI 等の既存譜面
- 将来的には既存のカラオケ譜面形式

参考データは絶対的な正解として扱わず、音声解析結果と照合するための強い証拠として扱う。

## 曲データ生成

原曲から以下を生成する。

- ボーカル音源
- 伴奏音源
- 歌詞
- 歌詞タイミング
- 採点用音程譜面
- 曲構造情報
- 各推定結果の信頼度
- 必要に応じて各モデルの根拠データ

生成した曲データはキャッシュし、歌唱のたびに重いAI解析をやり直さない。

## カラオケ再生

- ボーカルを除いた伴奏を再生できる
- 歌詞を同期表示できる
- 正解音程を音程バーとして表示できる
- ユーザーの歌唱音程をリアルタイム表示できる
- マイク入力をスピーカーへ返せる
- マイクへエコー / リバーブを適用できる
- 音楽音量を調整できる
- マイク音量を調整できる
- エコー量を調整できる
- 入力音程と期待音程を比較できる
- 採点できる

## 採点

初期段階では以下を中心にする。

- 音程
- タイミング
- ノートのカバー率

将来的な候補:

- ロングトーン
- 安定性
- ビブラート
- 抑揚
- 表現系評価

採点時はオーディオデバイス由来のマイク遅延を補正できる設計にする。

## 編集

自動生成結果は編集可能とする。

ただし通常フローでは、ユーザーに大量の修正を要求しない。

目標フロー:

1. AIが生成
2. 複数モデルとルールで検証
3. 低信頼箇所を自動再解析
4. 最有力結果を自動確定
5. 必要なユーザーだけ任意で微修正

低信頼箇所が残っていても、原則としてカラオケ開始を妨げない。

## 将来機能

- キー変更

- デュエット / 複数マイク
