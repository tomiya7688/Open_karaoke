# advisor運用（Open_karaoke）

公式: <https://code.claude.com/docs/en/advisor>（実験機能・Anthropic API限定）。
主モデルSonnetが日常作業を行い、強いモデル（Opus）を**判断が分かれる点だけ**に使って、使用量を下げつつ品質を保つ。

## 設定（このリポジトリの既定）

- `.claude/settings.json` の `advisorModel: "opus"`。主モデルはユーザー設定（Sonnet）。主モデルより下位のadvisorは自動で外れる。
- 一時変更は `/advisor <model>`、停止は `/advisor off`。`claude --advisor opus` は1セッションのみ。
- 主モデルがOpus以上のセッションでは、同格以上のadvisor（Opus 5以上かFable）だけが有効。

## 呼ぶ場面（このリポジトリ固有）

| 場面 | 呼ぶタイミング |
|---|---|
| Core / Analysis / GUI をまたぐ契約（API・SSE・保存形式・`format_version`・session/clock epoch・model plan固定）の設計や変更 | 方針確定の前 |
| リアルタイム境界（音声callbackへ重い処理を入れない、48 kHz整数sample index、遅延・drift） | 設計確定の前 |
| 同じテスト失敗・CI失敗が2回続いた | 3回目の修正の前 |
| 受入条件の解釈が分かれる（設計書とIssue・コードの不一致） | 実装前 |
| 実装完了の報告・PR作成・マージの前 | 成果物をcommit済みにしてから |
| レビュー（複数AI）の指摘が相反する、または重大度が判断できない | 修正方針の前 |

## 呼ばない場面

- 1〜数ツール呼び出しで終わる作業、整形、docs追記、ファイル検索、機械的なマージ・worktree片付け。
- 設計書に書かれた手順どおりの追加（テストの追加、既存パターンの複製）。
- 直前と同じ状態・同じ質問での再相談（advisorは毎回全会話を再読する。キャッシュされない）。
- 自分で一次情報（原文・実行結果）を取れるのに取らずに相談すること。先に調べてから相談する。

## 使い方の規則

1. 相談前に成果物を保存・commitする（セッションが切れても残る）。
2. 助言と自分が取った一次情報が食い違うときは、黙って切り替えずに相違点を示してもう一度相談する。
3. **advisorはレビュアーではない。** 外部AIレビューの証跡（`evidence.md`）の代わりにならず、記録もしない。`E:/projects/REVIEW_OPERATIONS.md` の手順は省略しない。
4. 呼出しは1作業につき通常 2〜3 回（方針確定前・行き詰まり時・完了前）。毎ターンは呼ばない。
5. 文脈が肥大化したセッション（150k超）では1回の相談が高コスト。区切りで新セッションへ引き継いでから相談する。
6. 読み取り専用の広範囲調査は `search` / `grep` / `docs` サブエージェントへ。advisorを調査代わりに使わない。

## 使用量の見方

`/usage` にadvisorの分もセッション合計として出る。advisor、主モデル、サブエージェントの内訳は計測できる範囲だけ報告し、できない値は未確認と書く。
