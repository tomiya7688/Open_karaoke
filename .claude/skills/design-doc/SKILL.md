# 設計書の書き方

1. `.claude/cloud-rules/DESIGN_DOCS_RULES.md` を読む（短い）。必要なテンプレートだけ開く: 目次 `INDEX_TEMPLATE.md`、機能 `FEATURE_TEMPLATE.md`、判断記録 `ADR_TEMPLATE.md`、AGENTS.md `AGENTS_TEMPLATE.md`。
2. 依頼対象: $ARGUMENTS（無ければ今回変更した機能）。
3. プロジェクトの `docs/README.md`（目次）を確認する。無ければ `INDEX_TEMPLATE.md` から作る。機能設計書は目次の表に行を追加し、冒頭の要約（目的・状態・最終確認日・親ページ・関連）を埋める。
4. 文書は日本語（です・ます調）が正本。1文書1目的。用語は用語集に合わせる。図はMermaidで書く（外部の描画サーバーは使わない）。重要な判断はADRに残す。
5. 設計を実装と同じ作業で更新する。実装と食い違う記述が残らないようにする。
6. 利用可能なら markdownlint でdocsを検査し、リンク切れを目視で確認する。指摘は直すか、理由を記録して除外する。
7. AGENTS.md・CLAUDE.md は長く書かず、目次へのリンクだけにする。

完了条件: 目次から変更対象の設計書へ辿れ、冒頭の要約・範囲・関連リンクが埋まり、検査を通っている。完了報告に新規・更新した設計書と検査結果を書く。
