# コメントルール要約（エージェント向け・短縮版）

正本は作者のローカルの仕様書（日本語）。この要約が、クラウドでの実用上の基準。

## 原則
- コメントは**日本語**で書く（項目名も日本語キーを使う）。
- クラス・関数・メソッドの宣言の**直前**に、JSON風コメント（JSON-like Comment Out）を置く。
- 関数・メソッド内部の処理単位・変数・理由は、**通常コメント**（日本語）で書く。JSON風にはしない。
- コメントは実装と一致させる。責務・処理・フィールド・入出力の意味が変わったら同じ作業で更新する。

## 対象と範囲
- 新規作成・変更したクラス・関数・メソッドに付ける。自明な1行のgetter等は省略可。
- 既存コードの一括書換えはしない。触った宣言だけ直す。生成物・vendor・外部コードは対象外。

## 項目（日本語キー）
| キー | 意味 | 値の形 | クラス | 関数/メソッド |
| --- | --- | --- | --- | --- |
| 責務 | 担当する役割 | `{"宣言名": "説明"}` | 必須 | 必須 |
| フィールド | 保持する主要な状態 | `{"フィールド名": "説明"}` | 必須 | - |
| 処理 | 主な処理（実行順） | 文字列の配列 | 推奨 | 必須 |
| 引数 | 入力 | `{"引数名": "説明"}` | - | 必須 |
| 戻り値 | 返す値 | `{"名前": "説明"}` か宣言順の配列。無ければ `[]` | - | 必須 |
| 副作用 | 外部・共有状態の変更 | `{"対象": "変更内容"}` | 任意 | 任意 |
| エラー | 重要な失敗条件 | `{"エラー名": "条件"}` | 任意 | 任意 |
| 補足 | 前提・制約 | 文字列の配列 | 任意 | 任意 |

## 書式（必須）
- 本文全体が有効なJSONオブジェクト。キーと文字列はダブルクォート、要素はカンマ区切り。末尾カンマ・本文中のコメントは禁止。
- 同じ意味のキーを1つのコメントに重複して書かない（`責務` と `Responsibility` を併記しない）。
- 責務のキーは宣言名、引数・フィールドのキーは実際の名前に合わせる。
- 未記入は `""`、記述対象なしは `{}` / `[]`。ただし完成時は埋める。任意項目は機械的に埋めない。
- トップレベルのキー順に意味を持たせない。配列（処理・複数戻り値）の順序には意味がある。

## 言語別の置き方
- TypeScript/JavaScript/C#/C++/Go/Rust: `/* ... */` のブロックコメントに本文を入れ、宣言の直前に置く。attribute/decorator がある場合はコメント→attribute→宣言の順。
- Python: 各行を `# ` で始めて本文を書き、`def`/`class` の直前に置く。

## 例（関数）
```ts
/*
{
  "責務": { "getUser": "ユーザーIDからユーザー情報を取得する" },
  "処理": ["userIdを検証する", "Repositoryからユーザーを取得する", "API返却形式へ変換する"],
  "引数": { "userId": "対象ユーザーのID" },
  "戻り値": { "user": "API返却形式のユーザー情報" },
  "エラー": { "NotFound": "対象ユーザーが存在しない" }
}
*/
function getUser(userId) {
  // userIdを検証する
  validateUserId(userId);
  // Repositoryが返した未整形のユーザー情報
  const user = repository.find(userId);
  // API返却形式へ変換して返す
  return toUserResponse(user);
}
```

## 完了条件
- 変更した宣言のコメントが有効なJSONで、必須項目が埋まり、実装と一致している。
- 内部の通常コメントも日本語。完了報告に、コメントを付けた/更新した宣言を書く。
